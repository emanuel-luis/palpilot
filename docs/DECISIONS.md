# Decisions

Low-impact decisions taken during the 2026-10 refactor, plus the answers to escalated ones.
Newest last.

| # | Date | Decision | Choice | Why |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-26 | Where refactor work happens | A git worktree per branch under `.claude/worktrees/` (already in `.git/info/exclude`) | The main checkout holds an uncommitted `CLAUDE.md` edit by the owner and the local Terraform state; switching its branch would put that edit on a feature branch. |
| 2 | 2026-10-26 | State backup before any Terraform command | Verified copies of `terraform.tfstate` and `.backup` in a local, gitignored `.state-backup/` (serial 289) | The state is local and holds secret values; one disk loss orphans every resource. |
| 3 | 2026-10-26 | Merge order while a merge to `main` is a deploy | PRs that touch only root files, `*.tf`, `docs/` or `.github/` go first (no deploy path); PRs that touch `coordinator/`, `frontend/` or `panel/` wait until a deploy is possible and are verified as no-op or smoke-tested first | `deploy.yml` fires only on those three paths. |
| 4 | 2026-10-26 | Deploys gated on CI | `deploy.yml` calls the reusable `ci.yml` and every deploy job `needs` it | The brief: deploy keeps running on `main` only after the PR checks pass. |
| 5 | 2026-10-26 | ci.yml triggers | Runs on pull_request, push to main with paths-ignore for coordinator/, frontend/, panel/, weekly schedule, workflow_dispatch and workflow_call. deploy.yml calls it first; both deploy jobs need it, keeping their existing if conditions. | Pushes that touch only deploy paths get CI once, through deploy.yml (mixed pushes run it twice, harmless), and a red check blocks the deploy. No workflow-level concurrency because the file is also called. |
| 6 | 2026-10-26 | IaC scanner | checkov 3.3.30 via uvx, pinned. No trivy or trivy-action. | Trivy action tags were hijacked in March 2026 (CVE-2026-33634). |
| 7 | 2026-10-26 | ruff scope | Rules E4, E7, E9, F, BLE selected explicitly; one per-file ignore of BLE001 for panel/panel.py. ruff format is enforced outside coordinator/ and panel/. | Defaults change between ruff releases. Formatting app code would touch deploy paths; the BLE001 is existing debt for an app-code PR. |
| 8 | 2026-10-26 | checkov findings | 16 existing findings recorded in the committed .checkov.baseline (generated on Linux so paths match CI); CI passes the baseline and fails only on new findings. | Fixing them needs semantic .tf changes, handled separately. Regenerate the baseline on Linux or WSL, not Windows. |
| 9 | 2026-10-26 | Node version in CI | Node 20 in ci.yml, same as deploy.yml. | Parity with deploy. Node 20 is EOL: bump both together later. |
| 10 | 2026-10-26 | tflint rules disabled | terraform_typed_variables is off (project_id, region, zone lack a type). | Adding type is a .tf edit, out of scope for the CI foundation. Follow-up. |
| 11 | 2026-10-26 | npm audit in security.yml | Deferred to the frontend tooling PR. | It reports a high zod advisory (GHSA-mrhx-c7xc-m3w5) today; the fix changes frontend/, a deploy path, so it ships with that PR instead of leaving a red check here. |
| 12 | 2026-10-26 | Provider lock platforms | .terraform.lock.hcl carries h1 hashes for linux_amd64, windows_386, windows_amd64 and darwin_arm64 (`terraform providers lock -platform=...`). | A lock written on Windows only held windows_386 hashes, so CI on Linux failed `validate` under `-lockfile=readonly`. Re-run the same command after any provider bump. |
| 13 | 2026-10-26 | Project status (program decision 24) | Offline by choice: billing stays disabled; no deploy, no `terraform apply`, no state migration; world data is not kept. | Owner's decision. The repo stays a maintained reference implementation. |
| 14 | 2026-10-26 | Deploy gate | Both deploy jobs in deploy.yml also require the repository variable `DEPLOY_ENABLED == 'true'` (unset). CI still runs on every push. | Without billing a deploy can only fail; a variable revives deploys without a code change. |
| 15 | 2026-10-26 | Terraform state | Stays local on the owner's machine (backed up, gitignored). The GCS backend ships as `backend.tf.example` + `backend.hcl.example`, with the steps in docs/REVIVAL.md. | A state bucket needs billing. |
| 16 | 2026-10-26 | Usage and cost analytics | DuckDB and Parquet (dbt-duckdb) over synthetic data in the `stats/history.jsonl` shape; no BigQuery, no GCP cost. | The real data is unreachable without billing, and the owner chose no recurring cost. |
| 17 | 2026-10-26 | Panel port 8080 | Left as is; the risk and the Direct VPC egress fix are in docs/SECURITY.md. | Nothing runs while offline, and the fix needs an apply window. |
| 18 | 2026-10-26 | npm audit in security.yml (row 11) | Resolved in the frontend checks PR: `npm-audit` job restored (`--omit=dev --audit-level=high`) together with the zod fix. | It was deferred because the zod advisory (GHSA-mrhx-c7xc-m3w5) was red and the fix touches frontend/, a deploy path. |
| 19 | 2026-10-26 | Frontend lint and tests | ESLint 9 flat config (typescript-eslint, react-hooks, react-refresh) and Vitest 4, run in the ci.yml frontend job before the build. rules-of-hooks is an error; no-explicit-any, exhaustive-deps and only-export-components are warnings (194 today). Vitest 4, not 5: 5 needs Node 22 and CI is on Node 20. | Zero errors from day one without behavior changes. The few existing violations are silenced with inline comments, not edited, so the shipped bundle stays byte-identical (verified by hashing the build before and after). |
| 20 | 2026-10-26 | zod bump | 4.4.3 to 4.6.7 (fix is 4.6.6 or later) | Clears GHSA-mrhx-c7xc-m3w5 so the restored npm audit passes. The built console is byte-identical, since the bundle does not include zod. Dev-only advisories (vite, vitest tooling, nanoid, postcss-selector-parser) remain, outside the production audit. |
| 21 | 2026-10-26 | Tailwind content scan | `tailwind.config.ts` excludes `src/__tests__/**` from `content`. | Test files are not UI; a word in a test (`block`) generated a new utility and changed the shipped CSS. With the exclusion the built console stays byte-identical to main. |
| 22 | 2026-10-26 | npm lockfile registry | 53 `resolved` URLs moved from a Lovable sandbox npm cache to registry.npmjs.org; integrity hashes unchanged. | The lockfile should not depend on a third-party build cache. `npm ci` with an empty cache fetched all of them from npmjs and passed the integrity checks. |
| 23 | 2026-10-26 | Built console in git | `coordinator/index.html` and `coordinator/assets/` are no longer tracked; CI builds them before tests, the container job and deploys. `coordinator/.gcloudignore` makes the Cloud Run upload set explicit (it keeps the built console, drops tests). | Build output in git drifts from the source. gcloud derives ignores only from a `.gitignore` inside the source dir, so an explicit list is safer than relying on it. |
| 24 | 2026-10-26 | Coordinator image | Two-stage Dockerfile: a builder installs the hashed `requirements.lock` (`--require-hashes`) into a venv; the runtime copies it, runs as UID 10001, keeps the same gunicorn CMD, asserts the console exists and has a HEALTHCHECK (Cloud Run ignores it; local and CI use it). | Non-root and reproducible installs. The frontend is not built inside the image because `gcloud run deploy --source=coordinator` only uploads `coordinator/`. |
| 25 | 2026-10-26 | Python lock for the image | `requirements.txt` stays the edited input; `make lock` regenerates `requirements.lock` for linux x86_64 and Python 3.12; the CI `container` job fails when it is stale. | Cloud Run runs linux x86_64 only. |
| 26 | 2026-10-26 | Base image pin | `python:3.12-slim` pinned by tag and digest, written literally in both FROM lines; Dependabot tracks `/coordinator`. | Dependabot does not resolve ARG values in FROM. |
| 27 | 2026-10-26 | Container smoke credentials | The CI smoke starts the image with a dummy `authorized_user` credentials file and a fake project. | `main.py` creates GCP clients at import time; nothing in the smoke reaches GCP. |
| 28 | 2026-10-26 | Analytics engine | DuckDB for storage and Parquet writes, dbt-duckdb for models and tests, pydantic v2 for the landing-to-raw contract, all in an opt-in `analytics` dependency group. | The real data is unreachable and the owner chose no GCP cost. The main CI never installs dbt. |
| 29 | 2026-10-26 | Synthetic data | A seeded generator writes the bucket layout of `stats/history.jsonl` (archive, `.1` rotation, live file) with a few deliberate defects (truncated line, duplicate, out-of-range, nulls). | Exercises the contract and rejects; the README of analytics/ says the data is synthetic and why. |
| 30 | 2026-10-26 | Unit costs | Only the README estimates: US$0.18 per VM-running hour and US$14 per month fixed floor (prorated 14/30 per calendar day). | The README labels $0.18 "per play-hour" but it is a compute+egress rate per running hour; the pipeline applies it that way. No other prices were invented. |
| 31 | 2026-10-26 | Reporting window | Explicit dbt vars `period_start`, `period_end` (exclusive) and `report_tz` (default America/Sao_Paulo); days are local days. A sample outside the window fails the build (`assert_samples_inside_period`). | Deriving the period from UTC sample dates added a phantom day to the demo (floor and always-on baseline inflated). |
| 32 | 2026-10-26 | Sample and session semantics | A sample counts until the next one, capped at 60 s when the gap exceeds 5 minutes (a new session). Null players count as none. The idle tail is everything after the last sample with a player. | Matches how the agent samples every 60 s only while the VM runs. |
| 33 | 2026-10-26 | Idempotent ingest | `run_id` is a digest of the input; a replay keeps the first `ingested_at`, so raw Parquet is byte-identical. The run JSON still records each execution's own start and finish. | Same input, same output, with honest run metadata. |
| 34 | 2026-10-27 | Diagram tool (program decision 32) | D2 v0.9.0, pinned by sha256 in the Makefile, ELK layout, light theme plus dark theme, the shared `docs/diagrams/_style.d2` of the program's pilot. SVGs are committed next to their sources. | Readable, reviewable diagrams as code; the same version and style in every portfolio repo. |

Not a required check. | The repo is private and pays for Actions minutes. `main` has no branch protection (the API answers "Branch not protected"), so there is no required-checks list to extend and a path filter cannot block a pull request. |
